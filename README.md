- 테스트: `npm test` (Node.js 내장 테스트 러너)
- 배포: `main` 브랜치 루트, GitHub Pages 자동 배포

## 네이버 지도 설정

네이버 Cloud 콘솔의 **Application Services → Maps → Application**에서 애플리케이션을 등록합니다.

1. Dynamic Map을 선택하고 Web 서비스 URL에 `https://mrsohnbit.github.io`를 등록합니다.
2. 인증 정보의 **Client ID**를 `config.js`의 `naverClientId`에 입력합니다.
3. 로컬에서 실제 지도를 확인하려면 콘솔에서 로컬 개발 URL도 허용해야 합니다.
4. 배포 페이지에서 지도 타일과 인증 실패 안내 유무를 확인합니다.

`ncpKeyId`는 브라우저 SDK에서 사용하는 공개 식별자입니다. Client Secret, OAuth 비밀키,
DB 관리자 키, 부서원 이메일 허용 목록, 비공개 리뷰는 이 공개 저장소에 넣지 않습니다.
클라이언트 ID의 허용 URL과 사용 한도는 네이버 콘솔에서 관리합니다.

공식 문서: https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html

## 현재 구현

- 모바일/데스크톱 반응형 화면, 접근성 라벨, 기본 확대 허용
- 네이버 지도 SDK 비동기 연결 및 인증 실패·로딩 지연·네트워크 오류 안내
- 기본 위치(서울시청), 사용자 요청 시 현재 위치, 지도 중심으로 검색
- 10~2,000m 반경(10m 간격), 300m/500m/1km 빠른 선택
- 사각형 영역과 드래그 가능한 두 꼭짓점, 영역 내 좌표 필터
- 식당/메뉴 검색, 음식 카테고리·메뉴 가격 필터, 거리·가격 정렬
- 조건에 맞는 메뉴 최대 3개 무작위 추천
- 이 브라우저의 localStorage에 저장하는 메뉴 즐겨찾기
- 식당 상세, 게스트/리뷰 준비 중 안내

## 데이터 및 미구현 범위

현재 6개 식당·메뉴·가격·좌표는 **전부 가상 예시 데이터**입니다. 실제 방문 안내가 아니며,
네이버 장소 검색 API를 호출하거나 네이버 리뷰/가격을 가져오지 않습니다.
예시 토글을 끄면 실제 데이터가 아직 없다는 빈 화면이 나옵니다.
기본 위치는 회사 위치가 정해지기 전 임시로 서울시청을 사용합니다.

Google 로그인, 부서원 인증, 비공개 리뷰와 별점 필터, 실제 식당/메뉴 DB는 아직 연결하지 않았습니다.
공개 Pages의 소스/JSON에 비공개 리뷰를 넣지 말고, 추후 인증된 백엔드에서 접근 권한을 검증해야 합니다.
현재 위치는 사용자가 버튼을 눌렀을 때만 요청하고 앱 DB/localStorage에는 저장하지 않습니다.
지도 표시에는 네이버 지도 서비스가 사용됩니다.
